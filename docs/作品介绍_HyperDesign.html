一、项目背景与行业痛点

在工业制造与硬件产品研发领域，生成式 AI（AIGC）的落地长期面临一道巨大的「车间鸿沟」——现有的图文生成与 3D 娱乐大模型虽能产出极具视觉冲击力的渲染图，却无法真正服务于生产制造。其核心症结在于四大行业痛点：

痛点 1：「像素幻觉」与「工程现实」脱节

传统 2D 生图工具（Midjourney / Stable Diffusion）生成的工业产品充斥违反物理规律的透视与光影伪影；主流 3D 生成模型导出的仅是拓扑杂乱、无物理毫米尺寸、非水密的三角网格（Mesh），无法直接用于 CNC 加工、注塑开模或钣金折弯。

痛点 2：缺乏可制造性设计（DFM）底层约束

通用大模型不具备企业私有的产线经验（特定机台的最小壁厚、拔模斜度、折弯扣除系数），生成方案常在结构评审阶段因无法脱模、壁厚不均或装配干涉而全盘推翻。

痛点 3：跨模态试错成本高昂

直接在参数化 CAD 阶段探索造型，修改周期极长；而在 2D 阶段探索，又缺乏自动化机制将「感性的视觉比例」无损还原为「理性的 B-Rep（边界表示法）参数化实体」。

痛点 4：数据隐私红线与模型进化难题

制造业核心工艺标准与历史图纸属高度机密，严禁上传公有云 API；同时企业需要一套零边际成本机制，把资深工程师日常的「审图判断」持续沉淀给本地模型，而非依赖昂贵算力集群重新预训练。

核心工程理念：设计可信度来自几何真实存在，而非像素逼真。 HyperDesign 打造了一套 100% 本地化部署、打通「概念发散 → 白模收敛 → 参数化 CAD → 生产工程图 → DPO 偏好自进化」全闭环的制造业 AI 系统。

二、系统技术架构

HyperDesign 采用「多环境隔离解耦 + 统一事务状态机（manifest.json）+ 显存红绿灯动态调度」的工程架构，将产品研发周期划分为 7 个紧密咬合的阶段。所有阶段的输入输出都汇聚到同一份 manifest.json 数据契约中，任一阶段可独立重跑而不破坏上下游。

三、核心应用场景

场景 1｜工业外壳与结构件敏捷开发（注塑 / 压铸）

场景描述：针对智能硬件外壳、工业传感器护罩、手持终端等产品，工程师仅需输入一句功能描述与安装尺寸包络，系统自动调取车间注塑机规范（如强制名义壁厚 2.4 mm、拔模角 ≥1.8°），在一次会话内完成从 4 组差异化造型探索到可报价 .step 实体模型的转化。

本机实证：4 张概念图 ≈ 9 min（114–136 s/张）→ TRELLIS 重建 32 s → Blender 清洗 9 s → CAD 代码生成 466 s → OCC 校验通过，产出 parametric_model.step（54.9 KB，BRep 合法）+ 参数化源码。

场景 2｜钣金与激光切割件快速排产（激光 / 数控折弯）

场景描述：针对设备支架、控制盒底座、法兰转接板等零件，系统生成参数化三维模型后，Phase 6 自动剥离图框与尺寸线，直出 1:1 纯净外轮廓与孔位 laser_1to1.dxf，可直接导入柏楚 CypCut 等激光切割 CAM 软件排料切割。

本机实证：proj_20261014_001_laser_1to1.dxf（TOP 投影 82 条轮廓实体，仅 CUT_PROFILE 图层、零尺寸线污染）。

场景 3｜非标机械零部件系列化派生

场景描述：Phase 5 产出的并非死模型，而是带顶部全局参数表的标准参数化源码（LENGTH_X、BOSS_INSET、WALL_THICKNESS 等），结构工程师只需修改变量，即可在 1 秒内派生出同产品家族不同规格的 .step 与 .dxf 图纸。

本机实证：05_cad/parametric_model.py 顶部参数表 + 注释齐全；自愈引擎即以此文件为「可复现资产」而非一次性脚本。

场景 4｜跨部门 / 外协供应商免插件三维协同审阅

场景描述：通过 Phase 4 的单文件便携打包器，将精修白模与包络标尺内嵌为独立 .html，客户、采购与外协模具厂无需安装笨重专业 CAD，在手机或浏览器中即可 360° 旋转并拖动滑块剖析内部腔体结构。

本机实证：04_viewer/proj_20261014_001_3D_Concept_Share.html（68 MB，GLB + 概念图 + manifest 全内嵌，双击即看，零服务器、零依赖）。

四、项目核心创新点

创新点 1｜提出「几何真实优先（Geometry-First）」的跨模态尺寸锚定机制

解决了从 2D 概念图 → 3D Mesh → 参数化 CAD 全过程中「物理尺寸丢失」的核心难题。系统通过全局事务契约 manifest.json 贯穿始终：Phase 3 用 Blender 将归一化网格强制对齐至真实毫米包络（坐平 Z=0 基准面），Phase 5 首创「白模三层高度（10% / 50% / 90%）激光切片采样法」，把感性的美学长宽高比例精确翻译为理性 CAD 代码的草图尺寸约束。

实测：三层截面分别输出 bottom_10pct / mid_50pct / top_90pct 的 z、span_x、span_y 锚点并注入建模提示词，最终 CAD 包络与目标值偏差为 0。

创新点 2｜基于 OpenCascade 硬件级反馈的 Text-to-CAD「自愈闭环（Self-Healing Loop）」

打破大模型写 CAD 代码「一次生成成功率低、拓扑易崩溃」的瓶颈。系统把生成的代码置于沙箱运行，直接调用 OpenCascade 底层内核做数学级检验：实体 isValid() 拓扑合法性、体积 > 1 mm³、三轴 Bounding Box 误差严控在 ±1.5 mm 内，并核查 STEP 实体文件确实落盘。一旦捕获 BRep_API: command not done 倒角报错或尺寸超差，自动把报错堆栈回传主控模型进行最多 5 轮自我修复；失败代码与成功代码同时被捕获为 DPO 负 / 正样本。

实测：示范项目第 1 轮一次通过；基准题 bench_01 上旧主控同样一次通过（体积 70,262 mm³，包络 120×80×45）。

创新点 3｜「客观 DFM 物理信号 > VLM 主观打分 > 人类终审」的三级评判体系

不同于纯视觉系统仅靠多模态大模型「看图打分」，HyperDesign 坚持工程物理规律一票否决权。Phase 7 中系统向网格内部发射 500 条反向法线射线（Ray-Casting）量化测量真实局部壁厚分布（取 10% 分位最薄处 p10 作为判据），并结合面法向量倾角统计拔模斜度、检查水密性与包络漂移（>8% 淘汰）。只有通过物理 DFM 硬指标的方案，才进入 VLM 视觉评分与人工选品台，彻底杜绝「好看但造不出」的废案。

实测：Phase 3 生成式白模被该体系判为「不通过」（水密=否、p10=1.51 mm、拔模 0.84°），系统随即改以「白模只作造型锚点、制造实体由 Phase 5 按工艺铁律重建」的路径推进——评判体系真实发挥了拦截作用。

创新点 4｜零边际成本的「日常工作即训练（Work-as-Training）」DPO 进化飞轮

把模型微调数据收集完全隐形化融入设计师日常工作流：Phase 4 审阅台中，设计师从 4 张方案里勾选 1 张推进 3D 时，系统自动把 (Brief, 选中 Prompt, 淘汰 Prompt) 组装为视觉偏好样本对；Phase 5 自愈循环中，自动把 (建模需求, 编译通过且尺寸合规的代码, 报错或超差的代码) 捕获为 CAD 代码偏好样本对。配合 Unsloth 本地 4-bit QLoRA 与 DPO（直接偏好优化）及黄金基准集回归测试，无需额外标注人力、无需云端算力费用。

实测：一次审阅提交即自动落盘 3 条 (prompt, chosen, rejected)；Unsloth QLoRA+DPO 训练链路完整跑通（LoRA 40.37 M 可训练参数 / 占 0.52%，3 步 27.6 s），并成功导出 GGUF Q4_K_M 注册进 Ollama。

创新点 5｜单机消费级硬件下的「显存红绿灯」接力与国标制图直连

针对本地工作站同时部署 LLM、FLUX、TRELLIS 等多个重型模型极易爆显存（OOM）的痛点，设计了严格的显存生命周期管理：Ollama keep_alive=0、ComfyUI POST /free、TRELLIS POST /unload 三者在阶段边界联动卸载，使单张消费级 16GB 显卡能够平稳接力百亿参数级多模态流水线。同时在末端内置 GB/T 机械制图图层规范（实线切割层 / 虚线隐藏层 / 关联标注层 / 图框标题栏分层），真正走完从 AI 到工厂车间的「最后一公里」。

实测：曾定位并修复 Windows 提交内存（commit limit）耗尽导致的 os error 1455——ComfyUI 默认 pinned memory 占用 43.9 GB，叠加 33 GB UNet 与 33 GB 文本编码器后触顶；关闭 pinned memory 并迁移 32 GB 模型库后全链路稳定。

诚实声明（工程取舍与限制）：
  1. 生成式白模的 DFM 不达标属行业固有现象：单图重建的网格不水密、壁厚与拔模不可控。HyperDesign 的应对是把它降级为「造型比例参考」，制造实体由 Phase 5 依据企业工艺规范重新参数化生成，并通过 OCC 数学校验——这也正是三级评判体系存在的意义。
  2. DPO 效果需要样本量：本次仅用 3 条偏好样本做机制验证，进化版（7B-Q4）在黄金基准上未超越旧主控（27B），守门员正确阻止了切流。按《工程文件》建议，攒够 50–100 条样本后再做正式进化。
  3. 本机 CadQuery/OCP 原生扩展无法加载（多个版本与解释器均复现），故 Phase 5/6 改用工程文件同样指定的 FreeCAD 自带 OpenCascade 内核；算法与交付物完全等价，CadQuery 版实现保留于仓库备查。
  4. 未启用的规划项：blender-mcp / freecad-mcp / CAD-COM 桥接在本机流程中未启用（全自动无头链路已覆盖需求），保留为人工精修接口。
